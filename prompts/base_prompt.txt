Analyse le mail reçu et extrais toutes les informations disponibles.

Réponds UNIQUEMENT avec un objet JSON valide, sans aucun texte avant ou après, sans balises markdown (pas de ```json), strictement au format suivant.

Si une information est absente, mets une chaîne vide "" (ou false pour les booléens, ou 1 pour nombre_techniciens).


Pour le bloc "customer", découpe strictement l'adresse en ses composants séparés :
- "adresse" doit contenir UNIQUEMENT le numéro et le nom de la rue (ex: "12 Avenue Jean Médecin"), 
  sans code postal, sans ville, sans pays.
- "code_postal" doit contenir uniquement le code postal (ex: "06000").
- "ville" doit contenir uniquement le nom de la ville (ex: "Nice").
- "pays" doit contenir uniquement le pays ou son code (ex: "FR" ou "France").
Pour le champ "pays" du bloc "customer", écris toujours le nom complet du pays en français et en toutes lettres (ex: "France", "Belgique", "Espagne", "Italie", "Pologne"), jamais un code ISO (pas "FR", pas "BE").
Règles de mapping précises pour le bloc "intervention" :

- "type" : utilise la valeur du champ du mail "Type de demande" si présent 
  (ex: "Maintenance", "Installation"). Ne mets JAMAIS le nom du client ici.

- "type_ticket" : utilise UNIQUEMENT "Incident" (si le mail décrit une panne, 
  un dysfonctionnement, quelque chose qui ne marche plus) ou "Demande" 
  (si le mail décrit une installation, un ajout de matériel neuf). 
  Ne mets JAMAIS le nom du client ici.

- "intitule" : reprends le sujet/objet du mail s'il existe, sinon résume 
  la demande en une courte phrase.

- "problematique" : copie le texte du champ "Intitulé de la demande" ou 
  "Description du problème" du mail, sans le reformuler.


Règles de mapping précises pour le bloc "procedure" :

- "travail_attendu" : décrit l'action technique concrète que le technicien 
  doit réaliser sur site (ex: "Remplacer le câble réseau", "Installer le 
  nouveau matériel", "Vérifier les connexions"). C'est le COMMENT technique.

- "consignes_mission" : décrit les contraintes ou conditions de planification 
  et d'organisation de la mission (ex: horaires à respecter, jours de 
  fermeture du site, instructions de prise de contact avant l'intervention). 
  C'est le QUAND/COMMENT s'organiser, pas l'action technique elle-même.

Ne mélange jamais les deux : une action technique va dans "travail_attendu", 
une contrainte d'organisation va dans "consignes_mission". Si le mail ne 
contient pas de contrainte de planification explicite, laisse 
"consignes_mission" vide plutôt que d'y mettre l'action technique par erreur.

Ne duplique jamais ces informations entre elles.
